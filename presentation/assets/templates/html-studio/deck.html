Argument architecture

A deck is an argument, not a stack of pages.

01 / EVIDENCE

Start with what can be defended

Sources, definitions, dates, assets, and caveats are explicit before layout decisions begin.

02 / CLAIM

Give each slide one job

The headline states the conclusion. The composition explains, proves, compares, or advances it.

03 / DECISION

Resolve the opening promise

Sequence and pacing should leave the audience with a judgment, action, or memorable model.

Editability evidence

Editable is reported, not assumed.

Native PowerPoint

Text, drawing shapes, links, notes, and semantic objects where the compiler creates them.

SVG vector

Sharp and transformable, but not automatically a semantic PowerPoint chart or diagram.

Raster fallback

Reserved for visual regions that cannot be represented faithfully as native or vector objects.

04
Describe downstream editing honestly by object class instead of applying one deck-level editable label.
Production principle

Build from the hardest frame outward.

One selected direction, one canonical source, and evidence for every claim made at delivery.
